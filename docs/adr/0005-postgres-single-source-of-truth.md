# ADR-0005：Postgres 唯一权威源，派生数据必须可重建

**状态**：已接受

## 背景

系统里有多种"数据"：正文、评论、会话、媒体文件、搜索索引、
浏览计数、HTTP 缓存。它们的一致性与持久性要求截然不同。

## 决策

1. **Postgres 是所有业务数据的唯一权威源（source of truth）。**
2. **任何派生数据都必须能从 Postgres 完整重建**：搜索索引、缓存、
   聚合计数、缩略图。
3. **绝不双写。** 需要把数据同步到第二个存储时，走 `outbox` 表 +
   worker 投递（表已在初始迁移中建好，但现在用不到）。
4. **对象存储里的原图是媒体原文的权威**，`media` 表只登记元数据；
   派生图（不同尺寸）是可重建的，允许被 GC 掉再生成。

## 理由

* 只要「能从权威源重建」，那么缓存、索引、副本全部变成**可丢弃**的，
  故障处理就从"必须恢复它"降级成"重建它"。
* 双写会带来经典的部分失败问题：Postgres 提交成功、Meilisearch 写入失败，
  两边永久不一致且无法自愈。outbox 把跨存储写入变成本地事务 + 可重试投递。
* 这条决策是**将来能加只读副本、加节点、换搜索引擎**的前提。

## 影响

* 每个派生存储都要配一个重建入口（例如 M4 的搜索索引全量重建命令）。
* `post_stats`（计数）是派生数据 —— 其权威是 `post_view_daily` 与 `likes`，
  因此计数出错时可以重算，不需要人工修数。
* 引入 Meilisearch 之类的第二存储时，`outbox` 表投入使用，
  并且 worker 必须是幂等的（同一事件重复投递不产生重复索引）。
