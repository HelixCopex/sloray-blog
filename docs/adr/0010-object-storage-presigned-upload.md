# ADR-0010：媒体用对象存储 + 浏览器预签名直传

**状态**：已接受

## 背景

博客需要存图片。可选：

1. 存本地磁盘，由 Caddy 直接提供静态文件；
2. 上传经过 API，API 再转存对象存储；
3. 对象存储（R2 / S3）+ 浏览器预签名直传。

## 决策

**方案 3。** 托管 S3 兼容对象存储（Cloudflare R2），
浏览器用 API 签发的预签名 URL 直接上传；API 只负责签发与登记元数据。
细节见 [`docs/media.md`](../media.md)。

## 理由

1. **方案 1 直接破坏"进程无状态"。** 本地磁盘成为不可重建的状态：
   加第二个节点后，用户会随机看到裂图；备份也要单独做一套。
   这是 ADR-0001 的"分布式就绪"清单第 1 条明令禁止的。
2. **方案 2 让 API 承担字节搬运。** 整个文件在 API 进程内存里过一遍，
   大图/慢网络下容易超时，还占满连接。API 应该只处理元数据。
3. **R2 的出网流量免费。** 图片是流量主体，这一条直接决定长期成本。
4. **预签名直传与无状态天然契合**：API 不需要临时目录、不需要分片、
   不需要在请求生命周期外持有任何东西。

## 影响

* **两个存储无法原子提交**，所以上传是两阶段：先直传对象，再登记数据库行。
  不一致时只允许"对象存在但没有行"（孤儿），由 GC 收敛；
  **绝不允许反过来**（行指向不存在的对象），那会直接产生无法自愈的裂图。
* **预签名 PUT 无法限制文件大小**——必须在登记时用 `HEAD` 校验实际
  `Content-Length`。若要上传前就卡住，得改用 POST Policy。
* **只公开派生图，原图归档到私有前缀**：图片重编码会自然剥离 EXIF（含 GPS），
  避免隐私泄漏。
* **禁止上传 SVG**：SVG 可内嵌 `<script>`，同域提供即等于存储型 XSS。
* 缓存策略依赖不可变性：**key 含 uuidv7，内容永不覆盖同 key**。
  要换图就生成新 key，否则 immutable 长缓存会持续供给旧内容。
* 删除必须显式 purge CDN（与 ADR-0003 的缓存失效是同一类问题）。

## 重新评估的触发条件

* 需要图片处理能力（按需裁剪、格式协商、人脸检测）→ 考虑引入 imgproxy 或
  Cloudflare Images，保持 API 不参与；
* 自建 MinIO 的运维成本低于托管费用时（目前不成立，单机自建还多一份备份责任）。
